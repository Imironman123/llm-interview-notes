## 1 Self Attention 的计算过程和复杂度分析

**答题主线** 输入 X 先经线性映射得到 Q、K、V，计算缩放点积得分，加入 Mask 后做 Softmax，再对 V 加权求和并经过输出投影。注意力矩阵让每个 token 能直接聚合全序列信息。

``` math
Attention(Q,K,V)\  = \ softmax(QKᵀ\ /\ \sqrt{}dₖ\  + \ M)V
```

- 若序列长度为 n、隐藏维度为 d，QKV 与输出投影约为 O(nd²)，注意力得分和加权求和约为 O(n²d)。长序列时二次项成为主要瓶颈。

- 训练时通常要保存注意力相关中间量，显存含 O(n²) 项；自回归解码使用 KV Cache 后，每个新 token 的注意力计算约为 O(nd)，但缓存随上下文线性增长。

- 多头并不会把总体渐进复杂度改成 O(hn²d)，因为每头维度通常是 d/h，总和仍约为 O(n²d)。

### 代码实现

> import math
>
> import torch
>
> import torch.nn as nn
>
> class SelfAttention(nn.Module):
>
> def \_\_init\_\_(self, d_model: int):
>
> super().\_\_init\_\_()
>
> self.q_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.k_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.v_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.out_proj = nn.Linear(d_model, d_model, bias=False)
>
> def forward(self, x, mask=None):
>
> \# x: \[batch, seq, d_model\]
>
> q, k, v = self.q_proj(x), self.k_proj(x), self.v_proj(x)
>
> scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
>
> if mask is not None:
>
> scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)
>
> weights = torch.softmax(scores.float(), dim=-1).to(scores.dtype)
>
> context = weights @ v
>
> return self.out_proj(context), weights

**常见追问** 继续追问时要区分训练阶段、prefill 阶段和 decode 阶段的复杂度，并说明 Flash Attention 主要降低 HBM 读写和中间显存，而不是改变精确注意力的 O(n²) 计算量。

## 2 为什么要除以 √dₖ

**答题主线** 如果 q 和 k 的各维独立、零均值且方差相近，点积方差会随 dₖ 线性增长。维度越大，logit 绝对值越大，Softmax 越容易饱和，梯度变小。除以 √dₖ 后把方差拉回稳定尺度。

``` math
Var(qᵀk)\  \approx \ dₖ\sigma ⁴，Var(qᵀk\ /\ \sqrt{}dₖ)\  \approx \ \sigma ⁴
```

- 缩放相当于固定温度，避免初始化阶段注意力分布过尖。

- 若改成其他归一化或可学习温度也能工作，但必须控制 logit 的尺度和数值稳定性。

## 3 Multi Head Attention 的作用和为什么不用单头

**答题主线** 多头把隐藏空间拆成多个子空间，让不同头并行学习位置、语义、指代、局部与全局等不同关系。拼接后再做输出投影，表达能力通常强于同等维度的单头。

- 单头只有一张注意力分布，容易把多种关系压在同一权重矩阵中。多头提供多组独立的 QKV 投影和注意力图。

- 头数并非越多越好。头维过小会限制每头容量，还可能出现冗余头。工程上同时考虑张量并行对齐、kernel 效率和 KV Cache 成本。

- GQA 和 MQA 通过共享 K/V 头降低缓存及带宽，但仍保留较多 Q 头维持表达能力。

## 4 KV Cache 的原理和显存占用计算

**答题主线** 自回归解码时，历史 token 的 K 和 V 不会因新 token 改变，因此每层缓存历史 K/V，只为新 token 计算一次 Q/K/V。这样避免每一步重复计算整个前缀。

``` math
M\_ KV\  = \ B\  \times \ L\  \times \ 2\  \times \ N\_ layers\  \times \ N\_ kv\_ heads\  \times \ d\_ head\  \times \ bytes
```

- B 是并发序列数，L 是已缓存 token 数，2 表示 K 和 V。若使用 FP16 或 BF16，每元素 2 字节。

- 例：32 层、32 个 KV 头、头维 128、上下文 4096、单序列 BF16，缓存约为 2 × 32 × 32 × 128 × 4096 × 2 字节，即约 2 GiB。

- 实际服务还要计入块粒度内部碎片、对齐、元数据、跨层缓存和 beam 数量。PagedAttention 用分页管理减少外部碎片并支持共享前缀。

## 5 GRPO 和 PPO 的区别以及 DeepSeek 使用 GRPO 的原因

**答题主线** PPO 通常训练策略模型和 Critic，使用价值函数估计优势；GRPO 对同一提示采样一组回答，用组内相对奖励标准化得到优势，不再单独训练 Critic。DeepSeekMath 和 DeepSeek R1 系列采用 GRPO，是因为推理任务可以从同题多答案的可验证奖励中获得稳定的相对信号，同时节省价值模型的显存与计算。

``` math
Aᵢ\  = \ (rᵢ\  - \ mean(r₁\ldots r\_ G))\ /\ (std(r₁\ldots r\_ G)\  + \ \varepsilon)
```

| **维度** | **PPO**                 | **GRPO**                          |
|:--------:|-------------------------|-----------------------------------|
| 优势估计 | Critic 或 GAE           | 同一提示的组内相对奖励            |
| 模型成本 | 策略 参考 奖励 Critic   | 策略 参考 奖励 无独立 Critic      |
| 适合场景 | 通用序列决策和密集反馈  | 可对同题多采样并可靠打分的任务    |
| 主要风险 | Critic 误差与训练不稳定 | 组内奖励过近时信号弱 采样成本较高 |

**常见追问** 不能只回答省掉 Critic。还要说明 GRPO 仍需要采样、多轮更新、KL 约束与重要性比率；奖励模型偏差、组大小和温度都会影响结果。

## 6 手写 Self Attention Python

**答题主线** 实现时要写清输入形状、缩放、Mask 广播和 Softmax 的数值稳定性。上面的实现返回输出与注意力权重，便于单元测试和可视化。

- Causal Mask 通常形状为 1×1×n×n 或 B×1×n×n，True 表示可见。

- 混合精度下可将 Softmax 临时转为 FP32，再转回原 dtype。

### 代码实现

> import math
>
> import torch
>
> import torch.nn as nn
>
> class SelfAttention(nn.Module):
>
> def \_\_init\_\_(self, d_model: int):
>
> super().\_\_init\_\_()
>
> self.q_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.k_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.v_proj = nn.Linear(d_model, d_model, bias=False)
>
> self.out_proj = nn.Linear(d_model, d_model, bias=False)
>
> def forward(self, x, mask=None):
>
> \# x: \[batch, seq, d_model\]
>
> q, k, v = self.q_proj(x), self.k_proj(x), self.v_proj(x)
>
> scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
>
> if mask is not None:
>
> scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)
>
> weights = torch.softmax(scores.float(), dim=-1).to(scores.dtype)
>
> context = weights @ v
>
> return self.out_proj(context), weights

## 7 项目中 RAG 的检索效果如何优化

**答题主线** 先把问题拆成召回、排序和生成三段，并建立可回放的标注集。没有离线评测集时，调 embedding、chunk 或 TopK 往往只能得到主观结论。

- 数据侧：清洗重复与过期文档，保留标题层级、表格语义和权限元数据；按语义边界切分并设置适度 overlap。

- 查询侧：意图分类、实体补全、同义词扩展、Multi Query、HyDE；对对话查询先做指代消解和独立问题改写。

- 召回侧：向量与 BM25 混合检索，按语言、时间、租户和权限做过滤；使用领域 embedding 并训练 hard negatives。

- 排序侧：先宽召回，再用 Cross Encoder 或 LLM reranker；做去重、多样性控制和父文档扩展。

- 评测侧：看 Recall@K、MRR、NDCG、上下文精确率与召回率，并最终看答案忠实度、引用正确率、拒答率、延迟和成本。

**常见追问** 回答项目效果时必须给出基线、数据集大小、指标变化和线上影响。例如 Recall@20 从多少提升到多少，P95 延迟增加多少，答案正确率是否真正改善。

## 8 MLA 的原理以及与 GQA 相比的优势

**答题主线** Multi Head Latent Attention 先把输入压缩成低维 KV latent，缓存 latent 而不是每个 KV 头的完整向量；计算注意力时通过上投影恢复所需表示。DeepSeek 的实现还把与 RoPE 有关的键分量解耦，便于吸收投影矩阵并控制缓存。

``` math
c\_ t\hat{}KV\  = \ W\hat{}DKV\ h\_ t，k\_ t\  = \ W\hat{}UK\ c\_ t\hat{}KV，v\_ t\  = \ W\hat{}UV\ c\_ t\hat{}KV
```

- GQA 让多个 Q 头共享同一组 K/V 头，缓存仍与 KV 头数和头维成正比；MLA 直接缓存共享低维 latent，压缩比可以更高。

- MLA 在较低缓存和解码带宽下，仍能通过不同上投影形成每个查询头所需的 K/V 表达，质量上限通常优于简单 MQA。

- 代价是实现更复杂，需要处理矩阵吸收、RoPE 解耦和专用 kernel；比较时应以真实 latent 维度与解耦位置缓存计算，而不是套用 GQA 公式。

## 9 Flash Attention 如何实现以及为什么更快

**答题主线** Flash Attention 把 Q、K、V 分块搬入片上 SRAM，按块计算得分并用 online softmax 合并局部结果，不在 HBM 中物化完整 n×n 注意力矩阵。它是 IO aware 的精确注意力算法。

``` math
m\_ new\  = \ max(m\_ old,\ max(S\_ block))，l\_ new\  = \ exp(m\_ old - m\_ new)l\_ old\  + \ \Sigma exp(S\_ block - m\_ new)
```

- 速度来源主要是减少 HBM 读写、融合 kernel、提高数据复用和避免大中间张量，而非减少渐进 FLOPs。

- 反向传播可保存少量归一化统计量并重算局部分数，以额外计算换显存。

- 块大小取决于 SRAM 容量、头维、dtype、寄存器压力和 occupancy。因果注意力还可跳过上三角块。

## 10 DPO 的数学推导

**答题主线** DPO 从带 KL 约束的奖励最大化出发。最优策略满足 π\*(y\|x) 与参考策略 π_ref(y\|x) 按 exp(r/β) 成比例，因此可把隐式奖励写成策略对数比。再把该奖励代入 Bradley Terry 偏好模型，直接得到对优选和劣选回答的二元交叉熵目标。

``` math
r\_\theta(x,y)\  = \ \beta\ log(\pi\_\theta(y|x)\ /\ \pi\_ ref(y|x))\  + \ C(x)
```

- 对偏好对 (y_w, y_l)，常数 C(x) 在奖励差中抵消。

- 最终优化 log σ(β\[(logπθ(y_w)-logπref(y_w))-(logπθ(y_l)-logπref(y_l))\]) 的负值。

- β 控制偏离参考模型的强度。β 较大时对相对 log ratio 更敏感，但不同实现对 β 与 KL 强弱的表述要结合目标定义说明。

**常见追问** 推导时要强调 DPO 不是没有参考模型，也不是直接最大化 chosen 的似然；它优化 chosen 与 rejected 相对参考模型的概率差。

## 11 如何设计 Agent 的记忆系统

**答题主线** 将记忆分为工作记忆、情节记忆、语义记忆和程序性记忆，并明确写入策略、检索策略、压缩策略和删除策略。记忆不是把所有历史对话塞进上下文，而是受权限和时效控制的外部状态。

- 工作记忆保存当前任务计划、工具结果和未完成状态，生命周期通常限于会话或任务。

- 情节记忆保存时间化事件与交互；语义记忆保存稳定事实和用户偏好；程序性记忆保存可复用流程与技能。

- 写入前做事实提取、置信度判断、去重、敏感信息识别和用户授权；记忆项带来源、时间、TTL、租户与可见范围。

- 检索使用语义相似度、关键词、时间衰减、重要性和任务相关性联合打分；召回后 rerank 并压缩到 token 预算内。

- 用版本、冲突检测和可撤销更新处理事实变化；为用户提供查看、纠正和删除入口。

## 12 MCP 和 Function Calling 的区别

**答题主线** Function Calling 是模型输出结构化工具名与参数的能力；MCP 是客户端与外部工具或数据源之间的标准协议，规定能力发现、资源、提示、工具调用和传输。前者解决模型怎样表达调用，后者解决生态怎样接入和互操作。

| **维度** | **Function Calling** | **MCP** |
|:--:|----|----|
| 抽象层 | 模型 API 的结构化输出 | 客户端与能力提供方的开放协议 |
| 能力发现 | 工具 schema 通常由应用预先注入 | 服务器可列出工具 资源 提示 |
| 通信 | 随一次模型请求返回调用意图 | 常见为 stdio 或基于 HTTP 的传输 |
| 关系 | 可作为 MCP 工具被模型使用时的最后一公里 | 可承载工具但不等于模型推理能力 |

**常见追问** 安全上都不能信任模型生成参数。应用必须做参数校验、权限检查、超时、幂等控制、审计和高风险操作确认。

## 13 设计一个支持多轮对话的大模型服务

**答题主线** 服务应把无状态推理和有状态会话分开。网关负责鉴权、限流和路由，会话层保存消息与摘要，编排层构造提示并执行工具，推理层负责 continuous batching 和 KV Cache，安全层做输入输出检查。

- 请求链路：API Gateway → Session Manager → Context Builder → Model Router → Inference Engine → Post Processor → Streaming Response。

- 上下文管理：最近窗口加滚动摘要，重要事实写入长期记忆；每条消息带版本号，避免并发请求覆盖。

- 推理优化：按模型和长度分池，prefill 与 decode 调度，PagedAttention，prefix cache，流式返回，超时与取消传播。

- 可靠性：请求幂等键、重试边界、熔断降级、跨可用区副本、会话存储持久化、工具调用状态机。

- 指标：TTFT、TPOT、tokens/s、P95 延迟、排队时间、KV 命中率、错误率、GPU 利用率、每千 token 成本和会话成功率。

## 1 Transformer 的整体架构以及 Encoder 和 Decoder 的区别

**答题主线** Transformer 由 token embedding、位置编码、多层注意力与前馈网络、残差连接和归一化组成。Encoder 使用双向自注意力编码完整输入；Decoder 使用因果自注意力逐 token 生成。经典 Encoder Decoder 的 Decoder 还包含对 Encoder 输出的交叉注意力。

- Encoder Decoder 适合输入输出边界明确的条件生成，如翻译、摘要和语音识别；Decoder Only 通过统一 next token prediction 获得更简单的扩展路径。

| **维度** | **Encoder**        | **Decoder**              |
|:--------:|--------------------|--------------------------|
| 可见范围 | 通常双向看完整输入 | 因果 Mask 只看历史 token |
| 主要输出 | 上下文化表示       | 下一个 token 概率分布    |
| 典型任务 | 分类 检索 编码     | 开放式生成 对话 代码     |
| 代表架构 | BERT               | GPT Llama Qwen           |

## 2 RoPE 旋转位置编码的原理

**答题主线** RoPE 把每两维看作二维平面，按 token 位置和频率对 Q、K 做旋转。旋转保持向量范数，且 q_m 与 k_n 的点积只依赖相对位置 m-n，因此把相对位置信息直接注入注意力得分。

``` math
\lbrack x'₂ᵢ,\ x'₂ᵢ₊₁\rbrack ᵀ\  = \ R(m\theta ᵢ)\lbrack x₂ᵢ,\ x₂ᵢ₊₁\rbrack ᵀ
```

- 低频维度变化慢，表达长距离位置；高频维度变化快，表达局部位置。

- 超出训练长度时相位可能外推失真，因此出现 Position Interpolation、NTK aware scaling、YaRN 等扩展方法。

## 3 LoRA 的原理以及秩 r 怎么选

**答题主线** LoRA 冻结原权重 W，只训练低秩增量 ΔW=BA，并用 α/r 缩放。假设任务适配所需的权重更新具有较低内在秩，从而显著减少可训练参数和优化器状态。

``` math
W'\  = \ W\  + \ (\alpha/r)BA，A \in R\hat{}(r \times d\_ in)，B \in R\hat{}(d\_ out \times r)
```

- r 越大容量越强，但参数、显存和过拟合风险上升。常从 8、16、32 做小规模消融，而不是仅按模型参数量决定。

- 数据少或任务接近基座能力时用较小 r；领域迁移大、目标模块多或多任务时提高 r。可按层分配 rank，优先 Q/K/V/O 与 FFN。

- 选择依据是验证集质量、稳定性、延迟和存储。若提高 r 后收益饱和，应把预算用于数据或目标模块选择。

## 4 RLHF 三个阶段分别是什么

**答题主线** 经典 RLHF 包括监督微调、偏好或奖励建模、强化学习优化三个阶段。现代流程可能用 DPO 等直接偏好优化替代显式奖励模型加 PPO，但目标仍是把模型行为向人类偏好和安全要求对齐。

- SFT：用高质量指令与回答训练模型遵循任务格式和基本行为。

- Reward Model：收集同一提示的多回答排序，训练模型输出标量偏好分数。

- RL：以奖励为目标更新策略，同时用 KL、clip 或参考模型约束，防止奖励黑客和能力漂移。

## 5 PPO 中 Critic 模型的作用

**答题主线** Critic 估计状态价值 V(s_t)，用来构造 advantage，回答当前动作比基线好多少。它不直接生成 token，而是降低策略梯度方差并给长序列分配更细粒度的信用。

``` math
A\_ t\  \approx \ \delta\_ t\  + \ \gamma\lambda\delta\_\{ t + 1\}\  + \ \ldots ，\delta\_ t\  = \ r\_ t\  + \ \gamma V(s\_\{ t + 1\})\  - \ V(s\_ t)
```

- LLM PPO 常在每个 token 位置输出 value，并结合最终奖励、逐 token KL 惩罚和 GAE 计算优势。

- Critic 训练不准会引入偏差和不稳定；它还增加一套模型参数、前向、反向和优化器状态。GRPO 正是用组内相对基线绕开独立 Critic。

## 6 GRPO 怎么去掉 Critic 以及优势是什么

**答题主线** 对每个 prompt 从当前策略采样 G 个回答，统一打分，再把每个回答相对组均值和标准差的偏离作为优势。因为同组共享 prompt，组内平均奖励充当输入相关的基线。

``` math
Aᵢ\  = \ (rᵢ\  - \ \mu\_ group)/(\sigma\_ group\  + \ \varepsilon)
```

- 优势是减少显存与训练复杂度，避免 value function 拟合误差，并适合数学、代码等可验证奖励。

- 代价是每个 prompt 需要多采样；若奖励几乎相同，标准化后的有效信号有限；组内相对优化也不等于绝对质量必然提升。

## 7 RAG 中 embedding 模型怎么选以及 chunk 大小怎么定

**答题主线** 模型选择看语言、领域、查询文档是否非对称、最大长度、向量维度、部署成本和许可证，并必须在自有检索集上评测。chunk 大小由信息完整性和检索精度共同决定，没有通用固定值。

- Embedding：先用 MTEB 或 C MTEB 等公开结果筛选，再用领域 query document 对和 hard negatives 验证 Recall@K、MRR、吞吐与存储。

- Chunk：按标题、段落、条款、函数或表格等语义边界切分；事实问答可较小，长论证或规章需保留更完整上下文。

- 常以 256 至 512 tokens 起步，设置 10% 至 20% overlap，再用 chunk size × TopK × rerank 的网格实验。数字只是起点，最终以评测和上下文预算决定。

## 8 BM25 和向量检索的区别

**答题主线** BM25 是基于词项匹配、逆文档频率和长度归一化的稀疏检索；向量检索把查询与文档映射到稠密语义空间，按余弦或内积找近邻。前者擅长精确词、编号和实体，后者擅长语义改写和同义表达。

``` math
BM25\  = \ \Sigma\ IDF(t)\  \times \ f(t,d)(k₁ + 1)\ /\ \lbrack f(t,d) + k₁(1 - b + b|d|/avgdl)\rbrack
```

- BM25 无需训练、可解释且更新简单，但跨词面语义能力弱。向量检索依赖 embedding 质量和 ANN 索引，可能漏掉罕见实体或精确数字。

- 生产 RAG 常做 hybrid search，再用 RRF 或学习排序融合，并加入 reranker。

## 9 手写 Multi Head Attention

**答题主线** 关键是把 d_model reshape 为 num_heads × head_dim，在头维上独立做注意力，再转置并 contiguous 后拼回。Mask 要能广播到 B×H×N×N。

- 实际项目优先调用 PyTorch scaled_dot_product_attention，以便自动使用 Flash Attention 或更合适的 fused kernel。

### 代码实现

> import math
>
> import torch
>
> import torch.nn as nn
>
> class MultiHeadAttention(nn.Module):
>
> def \_\_init\_\_(self, d_model: int, num_heads: int):
>
> super().\_\_init\_\_()
>
> assert d_model % num_heads == 0
>
> self.h = num_heads
>
> self.dh = d_model // num_heads
>
> self.qkv = nn.Linear(d_model, 3 \* d_model, bias=False)
>
> self.out = nn.Linear(d_model, d_model, bias=False)
>
> def forward(self, x, mask=None):
>
> b, n, d = x.shape
>
> qkv = self.qkv(x).view(b, n, 3, self.h, self.dh)
>
> q, k, v = qkv.unbind(dim=2)
>
> q, k, v = \[t.transpose(1, 2) for t in (q, k, v)\]
>
> scores = q @ k.transpose(-2, -1) / math.sqrt(self.dh)
>
> if mask is not None:
>
> scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)
>
> prob = torch.softmax(scores.float(), dim=-1).to(scores.dtype)
>
> y = (prob @ v).transpose(1, 2).contiguous().view(b, n, d)
>
> return self.out(y)

## 10 LRU Cache LeetCode 146

**答题主线** 哈希表提供 O(1) 定位，双向链表维护最近使用顺序。访问或更新后把节点移到表尾，超容量时删除表头最久未使用节点。Python 可用 OrderedDict 简洁实现。

- 面试若要求手写底层结构，应实现 Node、head/tail 哨兵、remove 和 add_to_tail 四个操作，get 与 put 均保持 O(1)。

### 代码实现

> from collections import OrderedDict
>
> class LRUCache:
>
> def \_\_init\_\_(self, capacity: int):
>
> self.capacity = capacity
>
> self.data = OrderedDict()
>
> def get(self, key: int) -\> int:
>
> if key not in self.data:
>
> return -1
>
> self.data.move_to_end(key)
>
> return self.data\[key\]
>
> def put(self, key: int, value: int) -\> None:
>
> if key in self.data:
>
> self.data.move_to_end(key)
>
> self.data\[key\] = value
>
> if len(self.data) \> self.capacity:
>
> self.data.popitem(last=False)

# 面经 3 字节跳动 搜索与推荐 2025 年 12 月

重点覆盖 tokenizer、归一化、优化器、混合精度、MoE、量化和投机解码。

## 1 BPE 分词算法的训练和推理过程

**答题主线** BPE 从字符或字节符号开始，反复统计语料中相邻符号对频次，合并最高频符号对并记录合并顺序。推理时对输入采用相同预切分，从初始符号开始按训练得到的优先级执行可用合并。

- 训练前要处理归一化、空格与词边界；Byte Level BPE 以字节为基础，可避免未知字符。

- 词表大小等于初始符号数加合并次数及特殊 token。较大词表缩短序列但增加 embedding 和 softmax 参数，也可能削弱形态组合泛化。

- 推理不能重新按当前文本频次选择 pair，必须按固定 merge ranks；工程上用链表、堆或 trie 优化重复扫描。

## 2 LayerNorm 与 BatchNorm

**答题主线** BatchNorm 对一个特征在 batch 和空间维统计均值方差，依赖 batch 统计并维护运行均值；LayerNorm 对单个样本的隐藏维统计，训练和推理一致，更适合变长序列和小 batch。

|  **维度**  | **LayerNorm**             | **BatchNorm**           |
|:----------:|---------------------------|-------------------------|
| 归一化范围 | 每个 token 或样本的特征维 | 同一通道跨 batch 和空间 |
| 依赖 batch | 否                        | 是                      |
|  训练推理  | 统计方式一致              | 推理使用运行统计        |
|  常见场景  | Transformer RNN           | CNN 大 batch 视觉任务   |

## 3 Pre Norm 与 Post Norm 以及为什么现在常用 Pre Norm

**答题主线** Post Norm 先做子层与残差相加再归一化；Pre Norm 先归一化再进入子层，残差主干更接近恒等映射，梯度能沿残差路径稳定传播，因此深层 Transformer 更容易训练。

- Pre Norm 通常减少对精细 warmup 和初始化的依赖，适合大模型和深网络。

- Post Norm 可能有更强的层间表示变换，但深层训练更容易梯度不稳定。现代模型也使用 RMSNorm、DeepNorm、Sandwich Norm 等变体，不能把 Pre Norm 说成唯一方案。

## 4 Adam 和 AdamW 的区别

**答题主线** Adam 把 L2 正则项的梯度加入参数梯度后再经过自适应缩放，因此各参数的衰减受二阶矩影响；AdamW 将权重衰减与梯度更新解耦，直接按参数比例衰减，更符合 weight decay 的定义。

``` math
AdamW：\theta\  \leftarrow \ (1 - \eta\lambda)\theta\  - \ \eta\ m\hat{}/(\sqrt{}v\hat{} + \varepsilon)
```

- 通常不对 bias、LayerNorm 或 RMSNorm 的缩放参数做 decay。

- 学习率与 weight decay 仍需联合调参；解耦并不表示所有任务上都无需正则化实验。

## 5 混合精度训练以及 BF16 与 FP16 的区别

**答题主线** 混合精度用低精度完成大部分矩阵计算，用 FP32 保存主权重、累积或敏感算子，以降低显存和提高 Tensor Core 吞吐。BF16 与 FP32 具有相同 8 位指数，动态范围大；FP16 指数仅 5 位，但尾数更长。

|  **属性**  | **BF16**           | **FP16**               |
|:----------:|--------------------|------------------------|
|   指数位   | 8                  | 5                      |
|   尾数位   | 7                  | 10                     |
|  动态范围  | 接近 FP32 不易溢出 | 较小 常需 loss scaling |
|    精度    | 有效数字较少       | 有效数字较多           |
| 大模型训练 | 硬件支持时通常更稳 | 老硬件常用             |

## 6 KV Cache 优化方法

**答题主线** 优化目标是减少每 token 缓存字节、提高缓存复用、降低碎片并避免无效上下文。模型结构、数值格式、内存管理和调度可以同时优化。

- 结构：MQA、GQA、MLA 减少 K/V 头或压缩 latent。

- 精度：FP8、INT8 或更低比特 KV 量化，按头或按通道设置 scale，并保留异常值处理。

- 管理：PagedAttention 分块分配，prefix cache 共享公共前缀，copy on write 支持 beam 和分支。

- 策略：滑动窗口、稀疏注意力、KV eviction 或基于重要性的 token 保留，但要验证长程信息损失。

- 系统：分层缓存、CPU offload、跨请求缓存、长度感知调度和缓存感知路由。

## 7 DeepSeek V3 的 MoE 架构设计

**答题主线** DeepSeek V3 使用 DeepSeekMoE 的细粒度专家与共享专家设计，并配合 MLA。论文配置约 671B 总参数、每 token 激活约 37B；每层包含共享专家和大量路由专家，token 只激活少数路由专家。

- 细粒度专家把传统大 FFN 拆得更细，给路由更多组合空间；共享专家承载跨 token 的通用知识。

- 论文配置为 1 个共享专家、256 个路由专家，每 token 选择 8 个路由专家。实现使用限制路由范围和负载均衡机制控制通信与热点。

- V3 引入 auxiliary loss free 的负载均衡思路，减少额外均衡损失对主任务的干扰；训练还结合 FP8 与多 token prediction。

- 回答时应区分总参数、激活参数和实际 FLOPs，并说明 MoE 的主要代价是 All to All 通信、负载不均和专家并行复杂度。

## 8 模型量化方法以及 GPTQ 和 AWQ 的区别

**答题主线** GPTQ 和 AWQ 都常用于训练后权重量化。GPTQ 基于近似二阶信息逐块量化并补偿误差；AWQ 根据激活统计识别重要权重通道，通过缩放保护这些通道，再进行低比特量化。

- 还应区分权重量化、激活量化、KV Cache 量化、静态与动态 scale、per tensor/per channel/per group。最终看真实任务精度和硬件 kernel，而不是只比较方法名。

| **维度** | **GPTQ**               | **AWQ**                       |
|:--------:|------------------------|-------------------------------|
| 核心依据 | Hessian 近似和误差补偿 | 激活感知的通道重要性          |
|   校准   | 少量数据估计二阶信息   | 少量数据统计激活并搜索缩放    |
|   特点   | 量化优化较精细         | 工程简单 常有高效 INT4 kernel |
|  共同点  | 多为 weight only PTQ   | 多为 weight only PTQ          |

## 9 投机解码的原理

**答题主线** 用较小 draft 模型连续提出多个 token，目标模型一次并行验证这些位置。按接受拒绝规则接收尽可能长的前缀；首个拒绝位置从修正分布采样，因此最终输出与单独从目标模型自回归采样的分布一致。

``` math
accept(x) = min(1,p(x)/q(x))；拒绝后从\ normalized\ max(0,p - q)\ 采样
```

- 加速来自把多个串行目标模型步骤合并成一次前向，但收益取决于接受率、draft 成本、候选长度和硬件并行度。

- 贪心解码可直接比较 draft token 与目标模型 argmax；随机采样必须使用严格的接受修正规则。

## 10 手写 BPE 分词器

**答题主线** 下面的简化实现展示训练时统计 pair 并合并、推理时按固定 merge rank 合并。真实实现还要处理预分词、Unicode 归一化、特殊 token、字节映射和高效数据结构。

### 代码实现

> from collections import Counter, defaultdict
>
> def train_bpe(words, num_merges):
>
> \# 词首空格或特殊起始符应在真实 tokenizer 中显式保留
>
> vocab = Counter(tuple(list(word) + \["\</w\>"\]) for word in words)
>
> merges = \[\]
>
> for \_ in range(num_merges):
>
> pair_freq = defaultdict(int)
>
> for symbols, freq in vocab.items():
>
> for pair in zip(symbols, symbols\[1:\]):
>
> pair_freq\[pair\] += freq
>
> if not pair_freq:
>
> break
>
> best = max(pair_freq, key=pair_freq.get)
>
> merges.append(best)
>
> new_vocab = Counter()
>
> a, b = best
>
> for symbols, freq in vocab.items():
>
> out, i = \[\], 0
>
> while i \< len(symbols):
>
> if i + 1 \< len(symbols) and symbols\[i\] == a and symbols\[i + 1\] == b:
>
> out.append(a + b)
>
> i += 2
>
> else:
>
> out.append(symbols\[i\])
>
> i += 1
>
> new_vocab\[tuple(out)\] += freq
>
> vocab = new_vocab
>
> return merges
>
> def encode_bpe(text, merges):
>
> rank = {pair: i for i, pair in enumerate(merges)}
>
> symbols = list(text) + \["\</w\>"\]
>
> while len(symbols) \> 1:
>
> pairs = list(zip(symbols, symbols\[1:\]))
>
> pair = min(pairs, key=lambda p: rank.get(p, float("inf")))
>
> if pair not in rank:
>
> break
>
> out, i = \[\], 0
>
> while i \< len(symbols):
>
> if i + 1 \< len(symbols) and (symbols\[i\], symbols\[i + 1\]) == pair:
>
> out.append(symbols\[i\] + symbols\[i + 1\])
>
> i += 2
>
> else:
>
> out.append(symbols\[i\])
>
> i += 1
>
> symbols = out
>
> return symbols

# 面经 4 字节跳动 Agent 平台 2025 年 12 月

重点是 Agent 架构、工具协议、错误恢复、多智能体协作和可靠性评估。

## 1 什么是 LLM Agent 以及核心组件

**答题主线** LLM Agent 是以大模型为决策核心、能够感知状态、规划步骤、调用工具、读写记忆并根据反馈继续执行的系统。与一次性问答的区别是它形成了跨多个动作的闭环。

- 模型与提示：理解目标、选择动作、生成结构化参数并总结结果。

- 工具层：搜索、代码、数据库、业务 API 等能力，带 schema、权限和错误语义。

- 规划与执行器：拆解任务、维护状态、控制最大步数、超时和终止条件。

- 记忆与上下文：会话历史、任务状态、长期事实和可复用技能。

- 安全与观测：策略校验、人工确认、日志、trace、成本和质量评测。

## 2 ReAct 框架的原理

**答题主线** ReAct 让模型交替产生推理状态和动作，环境返回 observation 后模型再决定下一步，直到给出最终答案。它把语言推理与工具反馈结合，能根据真实观察修正规划。

- 基本循环是 Thought → Action → Observation → Thought。生产系统通常不向用户暴露内部推理，而是保存结构化计划、动作与观察。

- 优势是简单、可解释、能处理中途信息；缺点是容易循环、错误传播、token 成本高，对工具描述和终止策略敏感。

- 工程上用状态机、最大步数、动作白名单、重复检测、观察压缩和 checkpoint 提升稳定性。

## 3 Function Calling 的工作流程

**答题主线** 应用把工具名、用途和 JSON Schema 随请求提供给模型。模型决定直接回答或返回工具调用；应用校验参数并执行工具，把结果作为 tool message 传回模型，模型继续推理并生成答案。

- 工具选择是模型建议，不是授权。执行前必须鉴权、校验枚举与范围、过滤注入内容，并限制网络和文件访问。

- 为写操作设置幂等键和确认机制；为长任务设置超时、取消与异步状态查询；工具返回结构化错误码，不要只返回自然语言。

- 并行工具调用适合彼此独立的读操作；有依赖的调用要按 DAG 或状态机串行执行。

## 4 MCP 协议的架构和通信方式

**答题主线** MCP 采用 Host、Client、Server 架构。Host 是承载模型和用户体验的应用；每个 Client 与一个 Server 建立会话；Server 暴露 tools、resources 和 prompts 等能力。协议消息采用 JSON RPC 语义，支持初始化、能力协商、请求、响应和通知。

- 本地集成常用 stdio，由 Host 启动子进程并通过标准输入输出通信。远程集成通常使用基于 HTTP 的可流式传输。

- Tools 是可执行动作，Resources 是可读取上下文，Prompts 是可复用提示模板；客户端可先列举再选择使用。

- MCP 标准化接入，但认证、租户隔离、用户同意、秘密管理、网络边界和审计仍由部署方负责。

## 5 Agent 如何处理多步骤任务的错误恢复

**答题主线** 把执行过程建模为持久化状态机或 DAG，每一步都有输入、输出、状态、重试策略和补偿动作。失败时先分类，再决定重试、换工具、回滚、重新规划或请求用户。

- 可重试错误：超时、限流、临时网络失败，使用指数退避、抖动和最大次数。

- 参数或计划错误：根据结构化错误修正参数，必要时回到最近 checkpoint 重新规划。

- 不可逆写操作：先预检，再用幂等键、事务或 saga 补偿；高风险操作要求人工确认。

- 防循环：记录动作签名和失败原因，检测重复轨迹，设定预算、截止时间和终止条件。

- 恢复后验证最终状态，而不是仅凭工具返回成功；全链路保留 trace 以便复盘。

## 6 多智能体系统的协作模式

**答题主线** 常见模式包括主管分工、流水线、并行专家、辩论评审和共享黑板。选择依据是任务依赖、是否可并行、协调成本、失败隔离和最终责任归属。

- 多 Agent 不会自动提高质量。必须给出明确角色、输入输出契约、停止条件、冲突解决、权限隔离和统一评测。

| **模式** | **机制**              | **适用场景**       | **风险**       |
|:--------:|-----------------------|--------------------|----------------|
| 主管分工 | 主 Agent 拆任务并汇总 | 复杂任务和异构工具 | 主管成为瓶颈   |
|  流水线  | 固定阶段依次传递      | 稳定业务流程       | 上游错误传播   |
| 并行专家 | 独立求解后聚合        | 检索 分析 多方案   | 重复成本和冲突 |
| 辩论评审 | 生成者与评审者迭代    | 高风险推理与代码   | 循环和迎合     |
| 共享黑板 | 围绕共享状态协作      | 动态环境和开放任务 | 并发覆盖与污染 |

## 7 如何评估 Agent 的准确性和可靠性

**答题主线** 以任务成功为主指标，并把最终结果、过程、工具使用、安全和系统性能分层评估。单看最终自然语言相似度无法定位失败。

- 结果：任务成功率、答案正确率、约束满足率、groundedness、用户纠正率。

- 过程：计划合理性、工具选择准确率、参数正确率、无效步骤数、恢复成功率。

- 可靠性：同一任务多次运行方差、长尾失败率、超时率、幂等性和状态一致性。

- 安全：越权率、提示注入成功率、敏感信息泄露、高风险操作未经确认的比例。

- 性能：完成时延、模型和工具 token、API 成本、并发吞吐。离线用固定任务集与模拟环境，线上用分桶 A B、人工抽检和真实成功事件。

## 8 设计一个带记忆的多轮对话 Agent

**答题主线** 使用最近消息窗口加滚动摘要维持会话连续性，将稳定事实写入长期记忆库，将当前任务状态写入工作记忆。每轮先检索相关记忆，再构造上下文，回答后判断是否写入。

- 长期记忆记录内容、来源、时间、置信度、租户、敏感等级和 TTL；记忆向量只用于召回，原文仍是事实依据。

- 写入策略优先保存用户明确偏好、长期项目事实和已确认决定，避免保存一次性闲聊、模型猜测或第三方敏感数据。

- 冲突时优先新近且由用户确认的事实，并保留旧版本；用户可以查看、修改和删除。

- 对话编排还要支持工具调用、失败恢复、摘要重建、token 预算和会话并发版本控制。

## 9 手写余弦相似度搜索函数

**答题主线** 先对查询和文档矩阵做 L2 归一化，再以矩阵乘法计算余弦分数。TopK 可用 argpartition 避免对全部结果完整排序。

``` math
cos(q,x)\  = \ qᵀx\ /\ (||q||₂\ ||x||₂)
```

- 大规模向量库通常使用 HNSW、IVF、PQ 等 ANN 索引；若向量预先归一化，余弦相似度等价于内积。

>
> def cosine_topk(query, matrix, k):

>
> x = np.asarray(matrix, dtype=np.float32)

> idx = idx\[np.argsort(-scores\[idx\])\]

# 面经 5 字节跳动 大模型算法 2025 年 11 月

重点是计算量、注意力变体、归一化、长上下文、偏好优化和幻觉。

## 1 Transformer 的 FLOPs 如何估算

**答题主线** 先按矩阵乘法的乘加记为 2 FLOPs 估算每层前向，再根据训练是否计入反向和参数梯度乘系数。对 Decoder 层，线性投影和 FFN 通常随 n·d² 增长，注意力随 n²·d 增长。

``` math
单层前向约\ 8nd²\  + \ 4n²d\  + \ 6ndd\_ ff\ FLOPs
```

- 8nd² 来自 QKV 和输出投影；4n²d 来自 QKᵀ 与 AV；标准两层 FFN 约 4ndd_ff，SwiGLU 有三次矩阵乘，约 6ndd_ff。

- 训练前向加反向常粗略按前向的约 3 倍估算，但具体取决于是否 checkpoint、MoE 激活比例、embedding 和损失。

- 业界也常用密集模型训练总计算约 6 × 参数量 × token 数做数量级估算。必须说明 FLOPs 口径，否则不同答案会相差一倍或更多。

## 2 GQA 的原理和实现

**答题主线** Grouped Query Attention 保留较多查询头，把若干 Q 头分成一组并共享一个 K/V 头。计算时将 KV 头逻辑扩展或在 kernel 内映射到对应 Q 组，从而降低 KV Cache 和解码带宽。

- 当 KV 头数等于 Q 头数时退化为 MHA；KV 头数为 1 时是 MQA。

- 缓存相对 MHA 的缩减比例约为 n_kv_heads / n_q_heads。模型质量通常介于 MHA 和 MQA 的权衡中。

- 实现时不应真的 repeat 大张量造成额外内存，最好由专用 attention kernel 按组索引。

## 3 SwiGLU 激活函数

**答题主线** SwiGLU 使用一个分支经过 SiLU 作为门，另一个分支提供内容，两者逐元素相乘后再下投影。门控让网络根据输入动态控制特征流，现代大模型中通常优于 ReLU 或普通 GELU FFN。

``` math
SwiGLU(x)\  = \ \lbrack SiLU(xW\_ g)\  \odot \ (xW\_ u)\rbrack W\_ d
```

- 为了保持参数或 FLOPs 接近普通 FFN，SwiGLU 的中间维度通常小于传统 4d，并按硬件对齐取整。

- SiLU(z)=z·sigmoid(z)，梯度平滑；门控带来第三个权重矩阵，也增加一次上投影计算。

## 4 RMSNorm 以及和 LayerNorm 的区别

**答题主线** RMSNorm 只按均方根缩放输入，不减去均值，通常也不需要 bias。它保留重缩放不变性，计算更简单，已广泛用于 Llama、DeepSeek 等模型。

``` math
RMSNorm(x)\  = \ x\ /\ sqrt(mean(x²) + \varepsilon)\  \odot \ g
```

| **维度** | **RMSNorm**   | **LayerNorm** |
|:--------:|---------------|---------------|
|  中心化  | 不减均值      | 减均值        |
|   缩放   | 均方根        | 标准差        |
|   参数   | 通常只有 gain | gain 和 bias  |
|   计算   | 略简单        | 略多          |

## 5 长上下文方案以及 NTK aware RoPE 的原理

**答题主线** 长上下文需要同时解决位置外推、注意力二次成本、KV Cache、训练数据和长程检索能力。只修改 RoPE 可以让位置范围变长，但不能自动解决显存、速度和真正利用长文的问题。

``` math
NTK\ aware\ scaling\ 对不同频率采用非均匀缩放\ \ 高频少改\ 低频更多扩展
```

- 位置：Position Interpolation、NTK aware scaling、YaRN、长上下文继续预训练。

- 计算：Flash Attention、滑动窗口、块稀疏、分层或线性注意力。

- 缓存：GQA、MLA、KV 量化、PagedAttention、prefix cache 和 offload。

- 能力：加入长文混合训练、位置均衡采样和 needle、multi hop、长文 QA 评测，防止只会读取开头结尾。

- NTK aware 的直觉是让高频位置模式保持局部分辨率，同时更强地拉伸低频维度以覆盖更长距离，比所有频率统一插值更少破坏已学表示。

## 6 DPO 和 RLHF 训练哪个更好以及各自优缺点

**答题主线** 没有绝对更好。若有稳定的离线偏好对且希望训练简单，DPO 通常成本低、稳定；若需要在线探索、复杂奖励组合或可验证环境反馈，奖励模型加 PPO 或 GRPO 更灵活。

- 实践中常用 SFT → DPO 得到强基线，再视任务加入可验证 RL；最终比较能力、安全、格式、长度偏好和成本，而不是只看单一 benchmark。

|  **维度**  | **DPO**                  | **PPO 类 RLHF**            |
|:----------:|--------------------------|----------------------------|
|  训练链路  | 偏好对直接优化           | 奖励模型 在线采样 策略优化 |
| 成本稳定性 | 较低 较稳定              | 较高 超参和系统复杂        |
|    探索    | 受离线数据覆盖限制       | 可从当前策略在线探索       |
|    奖励    | 成对偏好                 | 可组合规则 模型 环境奖励   |
|    风险    | 偏好噪声 过拟合 数据覆盖 | 奖励黑客 KL 漂移 训练不稳  |

## 7 GRPO 的优势函数怎么计算

**答题主线** 对同一 prompt 的 G 个输出得到奖励 r_i，按组均值和标准差归一化。结果可作为整条回答共享的序列级 advantage，也可结合过程奖励映射到 token。

``` math
Aᵢ\  = \ (rᵢ\  - \ mean(r₁\ldots r\_ G))/(std(r₁\ldots r\_ G) + \varepsilon)
```

- 有多个奖励时先做加权或规则组合；格式奖励、正确性奖励和安全奖励的尺度需校准。

- 若标准差接近零，要加 ε，并可跳过无差异组或增加采样多样性。组大小越大基线通常更稳，但采样成本增长。

- 策略更新仍使用新旧策略概率比、clip 和相对参考策略的 KL 约束。

## 8 大模型幻觉的原因和解决方案

**答题主线** 幻觉来自 next token 目标不保证事实正确、训练知识陈旧或冲突、上下文不足、检索失败、解码随机性、提示歧义以及奖励偏向流畅而非可验证。解决方案应按数据、模型、检索、生成和评测分层。

- 数据与训练：高质量去重语料、知识更新、引用训练、拒答数据、事实性偏好优化和工具使用训练。

- RAG 与工具：提高召回和 rerank，检查权限与时效，要求引用可追溯；数值、日期和数据库事实优先调用工具。

- 生成控制：明确证据边界、低温度、结构化输出、自检或 verifier、答案与证据一致性检查。

- 产品策略：不确定时澄清或拒答，高风险领域增加规则和人工复核。

- 评测：把知识错误、引用错误、无依据扩写、指令冲突分开统计，并监控校准度而非只看准确率。

# 面经 6 字节跳动 国际化 TikTok 2025 年 11 月

重点是注意力机制、数据训练、在线推理调度和解码算法。

## 1 Self Attention 为什么用 Softmax以及能否替换

**答题主线** Softmax 把任意实数得分转换为非负、和为一的权重，提供可微分的竞争机制，并可用 log sum exp 稳定计算。它让较高相似度获得指数级放大，适合内容寻址。

- 可以替换。Sparsemax 和 Entmax 产生稀疏分布；sigmoid attention 不要求和为一；线性注意力用核映射重排计算；cosine attention 控制 logit 范围。

- 替换后要重新考虑归一化、梯度、长度外推、数值稳定性和 kernel 支持。Softmax 的质量与成熟实现使其仍是主流。

## 2 Causal Mask 是什么以及为什么需要

**答题主线** Causal Mask 屏蔽当前位置之后的 token，使第 t 个位置只能看 0 到 t。训练时可并行输入完整序列，又不泄露未来答案，从而与自回归推理的条件分解一致。

``` math
Mᵢⱼ\  = \ 0\ if\ j \leq i\ else\  - \infty
```

- Padding Mask 处理无效填充，Causal Mask 处理未来信息，两者目的不同但可合并。

- prefill 使用下三角因果 Mask；单 token decode 的 Q 位于序列末尾，可看全部缓存历史。

## 3 Tokenizer 对模型性能的影响

**答题主线** Tokenizer 决定序列长度、词表参数、跨语言公平性、代码与数字表示以及输入输出成本。相同上下文窗口下，切分更高效的语言能容纳更多信息，但过大的词表会增加 embedding 和输出层。

- 多语言语料不均会导致某些语言 token 膨胀，推理更慢且训练曝光的有效文本更少。

- 数字、代码、空格、Unicode 和特殊字符切分影响算术、代码生成与安全过滤。Byte fallback 可避免 UNK。

- 更换 tokenizer 通常需要重新适配 embedding 和输出头，不能只在现有模型前替换。评测要看 fertility、压缩率、未知字符、下游质量和延迟。

## 4 SFT 数据质量与数量哪个更重要

**答题主线** 在预算有限时，质量通常优先，因为错误、模板化和冲突指令会直接塑造模型行为；但质量不能替代覆盖度，规模决定任务、语言、难度和长尾场景是否被看到。最佳策略是先建立高质量核心集，再有控制地扩量。

- 质量包括正确性、指令遵循、自然表达、难度、来源许可、去重和安全。

- 数量收益常递减。新增数据应优先填补评测暴露的薄弱能力，而不是重复简单问答。

- 用数据 ablation 和质量分桶判断边际收益，并防止 benchmark contamination、风格单一和合成数据自我强化。

## 5 PPO 中 KL 惩罚的作用

**答题主线** KL 惩罚限制新策略偏离参考策略，保留语言流畅性和基座能力，减少 reward hacking 与模式坍塌。LLM RLHF 常把逐 token log probability 差作为惩罚加入奖励。

``` math
r\_ total\  = \ r\_ reward\  - \ \beta\ \Sigma\_ t\ \lbrack log\pi\theta(a\_ t|s\_ t) - log\pi ref(a\_ t|s\_ t)\rbrack
```

- β 太小会导致策略漂移和奖励过优化，太大会抑制学习。可根据实测 KL 与目标 KL 自适应调整 β。

- PPO clip 约束相对旧策略的单次更新，KL 约束相对参考策略的长期漂移，两者并不重复。

## 6 GRPO 中 group 大小怎么选

**答题主线** group 越大，组内均值和方差估计更稳定，也更可能采到不同质量的答案；但 rollout 成本、显存和 wall clock 时间近似线性增长。选择要结合奖励方差、任务难度和并行采样能力。

- 奖励容易区分、输出多样性高时可用较小 G；稀疏奖励或难题需要更大 G 才有正负样本。

- 观察有效组比例、组内标准差、最佳答案率、梯度方差和每单位计算收益。若大量组奖励相同，单纯增大 G 可能不如改进采样温度或奖励。

- 常以 4 至 16 做实验起点，但不应把该范围当成固定结论。

## 7 PagedAttention 的原理

**答题主线** PagedAttention 把每个请求的 KV Cache 划分为固定 token 数的逻辑块，用块表映射到不连续的物理块。请求无需预留连续最大长度内存，从而减少碎片并支持按需扩容。

- 逻辑块类似虚拟内存页，attention kernel 根据 block table 读取物理 KV。

- 多个序列可共享前缀物理块，分支写入时 copy on write；适合 beam search 和 prefix cache。

- 收益是更高的 KV 内存利用率和并发度，代价是地址间接访问、块管理和专用 kernel 复杂度。块过大浪费尾部空间，过小增加元数据与访存开销。

## 8 Continuous Batching 是什么

**答题主线** Continuous Batching 在每个解码迭代动态加入新请求、移除已完成请求，而不是等整个静态 batch 的最长序列结束。它减少 padding 和空闲槽，提高 GPU 利用率与吞吐。

- 调度器根据 token 预算、KV 容量、优先级和延迟 SLO 选择本轮序列。prefill 过大会阻塞 decode，因此常做 chunked prefill 或分离调度。

- 与 PagedAttention 配合可按块增长缓存。关键权衡是吞吐与 TTFT、公平性、长短请求干扰和抢占成本。

## 9 手写 Beam Search 解码

**答题主线** 每一步扩展所有未完成 beam，对累计 log probability 加长度惩罚后保留最优 B 个序列。遇到 EOS 的 beam 保留但不再扩展；可加入 no repeat ngram 和 early stopping。

- Beam Search 更适合翻译等低熵任务，开放式对话常产生重复和保守文本，通常改用 top p、temperature 或多样性解码。

# 面经 7 字节跳动 飞书智能助手 2025 年 10 月

重点是企业 RAG 全链路、查询改写、rerank、评测和 Agent 规划。

## 1 完整描述 RAG 系统的架构

**答题主线** RAG 包含离线知识处理和在线问答两条链路。离线负责接入、解析、清洗、切分、embedding 和索引；在线负责查询理解、混合召回、rerank、上下文构造、生成、引用和评测。企业场景还必须把权限过滤贯穿索引与查询。

- 离线：连接器 → 文档解析/OCR → 去重与版本 → 语义切分 → 元数据和 ACL → embedding → 稀疏/向量索引。

- 在线：对话问题改写 → 意图和过滤条件 → BM25/向量/图召回 → 融合 → rerank → 去重和父文档扩展 → Prompt → LLM。

- 生成后：引用对齐、事实校验、拒答、安全过滤和反馈收集。

- 平台：索引增量更新、权限撤销、缓存、多租户隔离、可观测性、离线评测集和在线实验。

## 2 向量数据库选型 Milvus Weaviate Chroma

**答题主线** 先根据规模、可用性、过滤能力、混合检索、运维和生态选择。Chroma 适合本地原型；Milvus 适合大规模向量检索与多种 ANN 索引；Weaviate 提供较完整的 schema、过滤和混合检索体验。

- 选型必须用真实数据压测 Recall、QPS、P95、索引时间、增量写入、过滤选择率、备份恢复和总成本。若现有数据库已支持 pgvector 或 Elasticsearch，复用可能比引入新系统更合理。

| **产品** | **优势** | **适合** | **注意** |
|:--:|----|----|----|
| Milvus | 分布式规模 多索引 GPU 生态 | 大规模生产集群 | 组件与运维复杂度较高 |
| Weaviate | 对象 schema 过滤 hybrid API 完整 | 中大型应用平台 | 资源成本和版本特性需验证 |
| Chroma | 简单 嵌入式 开发快 | 原型 单机和测试 | 大规模 HA 多租户能力有限 |

## 3 查询改写方法 HyDE 和 Multi Query

**答题主线** 查询改写的目标是补全上下文、降低用户表达与文档表达的词汇差异。Multi Query 生成多个不同角度查询并合并结果；HyDE 先生成一个假想答案或文档，再用其 embedding 检索真实文档。

- Multi Query 提高召回和多样性，但会增加检索次数；需去重、RRF 融合并限制偏离原意。

- HyDE 对短、抽象查询有效，因为假想文本更接近文档分布；但生成错误细节可能把检索带偏。

- 多轮对话先做 standalone question rewrite 和实体解析。对精确编号、人名、错误码应保留原查询并加强 BM25，而不是只做语义扩写。

## 4 Reranking 的作用和常用模型

**答题主线** 首阶段召回追求高 Recall，reranker 对几十到几百个候选做更精细的 query document 相关性判断，提升 TopK 精度并减少送入 LLM 的噪声。

- Cross Encoder 将 query 和文档一起编码，质量高但成本随候选数增长；代表是 BGE reranker、Cohere Rerank 等。

- Late interaction 如 ColBERT 在精度和效率间折中；LLM rerank 可做 listwise 或 pairwise，但成本和稳定性要控制。

- 企业 RAG 可把语义相关性、权限、时效、来源质量和多样性合并打分。评测看 NDCG、MRR、Recall after rerank 与最终答案质量。

## 5 如何评估 RAG 系统以及 RAGAS 指标

**答题主线** RAG 评估要把检索和生成分开。检索有标注相关文档时看 Recall@K、MRR、NDCG；生成看答案正确性、忠实度、引用准确性、完整性和拒答。

- RAGAS 常用 faithfulness 衡量答案声明是否由上下文支持，answer relevancy 衡量回答是否切题，context precision 和 context recall 衡量检索上下文的精确与覆盖。

- LLM as judge 要做校准、抽样人工复核和版本固定，避免指标随评审模型漂移。

- 线上还看解决率、追问率、点击引用率、人工转接率、延迟和成本。建立错误 taxonomy，区分未召回、错排序、上下文截断和生成越界。

## 6 Agent 的 Planning 模块如何实现

**答题主线** Planning 将目标转成可执行步骤并根据观察动态更新。简单任务用 ReAct 即时规划；稳定流程用工作流或 DAG；开放复杂任务可采用 plan and execute，先产出高层计划，再由执行器逐步完成。

- 计划项应包含目标、输入、工具、依赖、成功条件和失败分支，而不是只有自然语言待办列表。

- 执行中持续检查已满足条件，必要时 replan；用状态机保存 checkpoint，避免每次从完整聊天重新推断。

- 可加入 task decomposition 示例、工具能力约束、成本估计和 verifier。高风险流程优先使用确定性工作流，把 LLM 限制在需要判断的节点。

## 7 手写 KV Cache Attention

**答题主线** 解码阶段输入单个新 token，只计算其 q、k、v，将新 k/v 追加到缓存，然后 q 对完整缓存做注意力。真实服务用预分配或分页写入，不能每步 torch.cat，因为会重复复制。

- 若使用 RoPE，通常在写入缓存前对 K 应用位置旋转；缓存布局要匹配 kernel，例如 B×H_kv×L×D_h 或分页块布局。

### 代码实现

> import math
>
> import torch
>
> def decode_attention(q, k_new, v_new, cache_k, cache_v):
>
> \# q/k_new/v_new: \[B, H, 1, Dh\]
>
> k = k_new if cache_k is None else torch.cat(\[cache_k, k_new\], dim=-2)
>
> v = v_new if cache_v is None else torch.cat(\[cache_v, v_new\], dim=-2)
>
> score = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
>
> prob = torch.softmax(score.float(), dim=-1).to(q.dtype)
>
> output = prob @ v
>
> return output, k, v

## 8 LRU Cache 设计

**答题主线** 哈希表加双向链表实现 O(1) get 和 put。生产缓存还需定义容量口径、TTL、淘汰回调、并发锁、统计指标、缓存击穿和一致性策略。

- 分布式场景的 LRU 通常只保证单节点局部近似，热点、分片和副本使全局严格 LRU 成本很高；可结合 LFU、TinyLFU 或按字节加权。

### 代码实现

> from collections import OrderedDict
>
> class LRUCache:
>
> def \_\_init\_\_(self, capacity: int):
>
> self.capacity = capacity
>
> self.data = OrderedDict()
>
> def get(self, key: int) -\> int:
>
> if key not in self.data:
>
> return -1
>
> self.data.move_to_end(key)
>
> return self.data\[key\]
>
> def put(self, key: int, value: int) -\> None:
>
> if key in self.data:
>
> self.data.move_to_end(key)
>
> self.data\[key\] = value
>
> if len(self.data) \> self.capacity:
>
> self.data.popitem(last=False)

# 面经 8 字节跳动 AI Infra 2025 年 10 月

重点是多维并行、ZeRO、集合通信、CUDA 和大模型在线服务。

## 1 大模型分布式训练的并行策略

**答题主线** 常见并行维度包括数据并行、张量并行、流水线并行、序列或上下文并行、专家并行以及参数或状态分片。实际训练通常组合为 3D 或 4D 并行。

- 数据并行复制模型、切分 batch，计算效率高但参数和优化器状态重复。FSDP/ZeRO 将状态分片。

- 张量并行切分单层矩阵，降低单卡参数和计算，但每层都有 All Reduce 或 Reduce Scatter，要求高速节点内互联。

- 流水线并行切分层，通信量较小但有 bubble，需要 micro batch 和调度。

- 上下文并行切分长序列的 attention；专家并行把 MoE 专家分到设备，通过 All to All 路由 token。

- 选择依据是模型能否单卡放下、序列长度、网络拓扑、batch、显存、通信计算比和故障域。

## 2 DeepSpeed ZeRO 三个阶段的区别

**答题主线** ZeRO 按数据并行组分片训练状态。Stage 1 分片优化器状态；Stage 2 再分片梯度；Stage 3 继续分片参数，并在前向或反向需要时 All Gather。阶段越高显存越省，通信调度和实现复杂度越大。

- 对 Adam 混合精度训练，优化器状态通常占大头。Stage 3 的实际效率依赖 bucket、预取、参数持久化阈值和网络带宽。

| **阶段** | **分片内容** | **主要通信** | **特点** |
|:--:|----|----|----|
| Stage 1 | 优化器状态 | 梯度 All Reduce | 改动小 节省 Adam 状态 |
| Stage 2 | 优化器状态和梯度 | Reduce Scatter 与参数同步 | 进一步省显存 |
| Stage 3 | 参数 梯度 优化器状态 | 频繁参数 All Gather | 显存最省 可 offload |

## 3 张量并行和流水线并行怎么选

**答题主线** 张量并行适合单层矩阵太大或希望在节点内高速互联上协同计算；流水线并行适合模型层数多、可按层均衡切分并跨节点扩展。生产上通常节点内 TP、节点间 PP 再叠加 DP。

| **维度** | **张量并行**   | **流水线并行**             |
|:--------:|----------------|----------------------------|
| 切分对象 | 单层权重和激活 | 连续层段                   |
| 通信频率 | 几乎每层       | 阶段边界                   |
| 网络要求 | 高 带宽低延迟  | 相对较低                   |
| 主要损失 | 集合通信       | pipeline bubble 和负载不均 |
| 适合拓扑 | NVLink 节点内  | 跨节点                     |

## 4 All Reduce 和 Ring All Reduce 的区别

**答题主线** All Reduce 是把所有设备的数据做规约并把结果发送给所有设备的集合操作；Ring All Reduce 是一种具体算法，通常分 Reduce Scatter 和 All Gather 两阶段，设备按环与相邻节点传输分块。

- Ring 对大消息带宽利用率高，每设备传输约 2(N-1)/N 倍消息大小，但需要 2(N-1) 个通信步骤，延迟随设备数增加。

- 树形或分层算法对小消息和大规模节点的延迟更好。NCCL 会根据拓扑、消息大小和网络选择 ring、tree 等算法。

- 区别不是 All Reduce 与 Ring 二选一，而是语义与实现算法的关系。

## 5 梯度累积的作用和实现

**答题主线** 梯度累积用多个 micro batch 的反向结果累加后再做一次 optimizer step，得到更大的有效 batch 而不增加单步激活显存。有效 batch = micro batch × 累积步数 × 数据并行卡数。

- 每个 micro batch 的 loss 通常除以 accumulation_steps，避免梯度放大。非更新步不 zero_grad、不 optimizer.step。

- DDP 中可在中间 micro batch 使用 no_sync，避免每次反向都通信，最后一次再规约。

- 代价是参数更新频率下降、wall clock 增加；学习率、warmup 和梯度裁剪要按有效 batch 与更新步口径调整。

## 6 vLLM 的架构和核心优化技术

**答题主线** vLLM 是面向高吞吐 LLM 推理的引擎。核心是调度器持续组织请求、worker 执行模型、PagedAttention 管理 KV Cache，并通过 continuous batching 动态复用 GPU。

- 内存：PagedAttention、prefix caching、chunked prefill、可选 KV dtype 和 swap/offload。

- 调度：token budget、抢占、优先级、prefill decode 混合或分离，以及流式输出。

- 执行：张量与流水线并行、CUDA Graph、fused kernel、quantization、speculative decoding 等。

- 服务：OpenAI 兼容 API、模型加载、请求队列、分布式 executor 和观测。评估要同时看吞吐、TTFT、TPOT、P99 和公平性。

## 7 CUDA kernel 优化的基本方法

**答题主线** 先用 profiler 确认瓶颈是内存带宽、计算、延迟还是 launch overhead，再针对访存、并行、融合和数值精度优化。盲目改线程数通常无效。

- 访存：coalesced access、对齐和向量化加载、共享内存复用、减少 HBM 往返和 bank conflict。

- 并行：合理 block/warp 映射，控制寄存器和共享内存以保持 occupancy，减少 warp divergence。

- 计算：使用 Tensor Core、合适 tile、混合精度、流水化拷贝与计算。

- 融合：把 elementwise、bias、activation、norm 等合并，减少 kernel launch 和中间张量。

- 验证：对比数值误差，覆盖不同 shape，报告 kernel 时间、带宽、TFLOPS 与端到端收益。

## 8 如何设计一个大模型推理服务

**答题主线** 从模型网关、调度、推理引擎、KV 内存、分布式部署、弹性与观测六层设计。目标是在质量约束下满足 TTFT、TPOT、吞吐、可用性和成本。

- 入口：鉴权、配额、限流、模型路由、请求大小限制和流式协议。

- 调度：长度预测、continuous batching、chunked prefill、优先级、公平性、取消和背压。

- 引擎：PagedAttention、prefix cache、量化、CUDA Graph、speculative decoding 和并行策略。

- 集群：按模型分池，拓扑感知放置，健康检查，滚动升级，故障重试和容量 autoscaling。

- 观测：队列、TTFT、TPOT、tokens/s、KV 利用率、batch 大小、GPU 利用率、OOM、错误率和每 token 成本。

# 面经 9 字节跳动 安全与治理 2026 年 2 月

重点是威胁模型、越狱与提示注入防御、对齐训练、红队流程和偏见治理。

## 1 LLM 常见的安全风险

**答题主线** 风险可分为内容安全、应用安全、数据与隐私、模型供应链和自主行动风险。具体系统先建立资产、攻击面、攻击者能力和可接受风险，再选择控制措施。

- 有害内容与误导：违法指导、自伤、仇恨、医疗金融错误、深度伪造和大规模操纵。

- 提示攻击：越狱、直接或间接提示注入、系统提示泄露、工具参数操纵。

- 数据风险：训练数据泄露、成员推断、敏感信息记忆、RAG 越权和日志泄露。

- 应用风险：过度授权工具、SSRF、代码执行、任意文件访问、供应链和插件风险。

- 治理风险：偏见歧视、不可解释、版权、合规、模型更新后行为漂移。

## 2 越狱攻击的类型和防御

**答题主线** 越狱试图绕过模型行为约束，常通过角色扮演、指令混淆、编码变形、多轮诱导、对抗后缀、多语言迁移或利用模型对虚构场景的服从。防御应采用多层控制，不能依赖单一系统提示。

- 训练：安全 SFT、偏好优化、对抗数据和拒答校准。

- 输入：分类器、规则、规范化、对抗后缀检测和速率限制，但避免误伤正常研究。

- 输出：策略分类、事实或格式校验、敏感内容拦截和安全替代回答。

- 工具：最小权限、沙箱、参数校验、网络 allowlist、用户确认和审计。

- 运营：持续红队、canary、分版本评测和快速回滚。攻击会适应防御，因此要按成功率和业务损害评估。

## 3 提示注入如何防范

**答题主线** 把外部文本视为不可信数据，而不是可执行指令。系统应保持指令与数据的结构边界，由应用执行权限决策，并限制工具能访问的资源。

- 直接注入来自用户输入，间接注入藏在网页、邮件、PDF 或工具结果中。后者尤其危险，因为 Agent 可能把检索内容当命令。

- 将系统指令、用户任务、检索内容和工具输出放入明确字段；提示外再做 deterministic policy，禁止文档内容提升权限。

- 工具采用 capability token、最小权限、参数 schema、域名和路径 allowlist；读写分离，高风险写操作二次确认。

- 敏感秘密不应出现在模型上下文；对输出做数据泄露检测。用包含诱饵指令的测试集验证攻击成功率。

## 4 RLHF 对齐训练如何增强安全性

**答题主线** RLHF 可用安全示范和偏好数据训练模型拒绝危险请求、遵循边界并提供有帮助的安全替代回答。奖励模型或偏好目标把安全行为转成可优化信号。

- SFT 教会基本策略和拒答格式；偏好训练比较安全与不安全回答；RL 可在对抗提示上进一步优化。

- 安全数据要覆盖多语言、多轮、隐式意图和边界案例，并平衡 helpfulness，避免过度拒答。

- 局限包括 reward model 被绕过、分布外攻击、标注偏差和表面对齐。训练不能替代工具权限、输入输出防护和运营监控。

## 5 Red Teaming 的流程

**答题主线** 先定义威胁模型和范围，再建立攻击分类与测试集，执行人工和自动攻击，按可利用性与影响分级，修复后回归验证并持续监控。

- 准备：资产、用户、工具权限、数据边界、合规要求和成功判据。

- 攻击：越狱、提示注入、数据泄露、工具滥用、偏见、幻觉、资源消耗和多轮组合攻击。

- 记录：完整提示、模型版本、参数、工具 trace、是否成功、影响和复现条件。

- 修复：数据与训练、提示、策略引擎、权限、沙箱、UI 确认和速率限制。

- 复测：独立回归集、未见攻击、误杀率、残余风险和上线门槛；重大问题建立披露与响应流程。

## 6 大模型的偏见检测和缓解

**答题主线** 先定义受保护群体、任务和伤害类型，再用群体级指标、成对反事实测试和人工质检测量。偏见可能来自数据、标注、模型、提示、检索和产品决策。

- 检测：不同群体的错误率、拒答率、毒性、推荐曝光、刻板印象关联和校准度；用只替换群体属性的 paired prompts 做反事实比较。

- 缓解：平衡与去偏数据、标注指南、偏好优化、约束解码、RAG 来源治理、敏感属性最小化和人工复核。

- 必须同时报告总体质量和各子群体置信区间。简单追求各组输出完全相同可能掩盖真实需求差异，应由明确公平目标和法律政策指导。

# 面经 10 字节跳动 推理优化 2026 年 1 月

重点是三类注意力缓存、Flash Attention 细节、分布一致的投机解码、量化和端到端延迟。

## 1 KV Cache 显存公式 MHA GQA MLA

**答题主线** MHA 和 GQA 都可用 KV 头数公式计算；MLA 要按实际缓存的低维 latent 和解耦 RoPE 分量计算。所有公式还要乘 batch、缓存长度、层数和每元素字节数。

``` math
M\_ MHA/GQA\  = \ B \cdot L \cdot N\_ layers \cdot 2 \cdot N\_ kv\_ heads \cdot d\_ head \cdot bytes
```

- 例：若 GQA 的 H_q=32、H_kv=8，则缓存约为同头维 MHA 的四分之一。

- MLA 不能写成固定通用倍率。以模型配置中的 kv lora rank、rope head dim、是否共享位置键为准，并确认 K/V 是否共用同一 latent。

- 服务容量还要计入块尾浪费、beam 或并行候选、前缀共享、量化 scale 与元数据。

| **结构** | **每层每 token 缓存元素** | **说明**                              |
|:--------:|---------------------------|---------------------------------------|
|   MHA    | 2·H_q·d_h                 | K 和 V 头数都等于查询头数             |
|   GQA    | 2·H_kv·d_h                | H_kv 小于 H_q 按分组共享              |
|   MLA    | d_c + d_rope 或按实现口径 | 缓存 KV latent 以及不可吸收的位置分量 |

## 2 Flash Attention 的 tiling 策略和 online softmax

**答题主线** 将 Q 按行块、K/V 按列块加载到 SRAM。对一个 Q 块遍历 K/V 块，计算局部得分，并维护每行已见分数的最大值 m、指数和 l、未归一化输出累加器 O。新块到来时按新的最大值重缩放旧统计量。

``` math
m'\  = \ max(m,\ rowmax(S));\ l'\  = \ exp(m - m')l\  + \ rowsum(exp(S - m'))
```

- 输出累加器同样乘 exp(m-m') 后加上 exp(S-m')V，遍历完再除以 l。该递推与整行 Softmax 数学等价。

- Q 块驻留可复用多个 K/V 块，块尺寸受 shared memory、寄存器、头维和 warp 配置限制。

- 因果模式跳过完全位于未来的 tile，并在对角 tile 内做 mask。反向重算局部分数以避免保存 n² 注意力矩阵。

## 3 投机解码为什么能保证输出分布一致

**答题主线** 设目标分布为 p、draft 分布为 q。draft token x 以 min(1,p(x)/q(x)) 接受。被接受的概率质量为 min(p(x),q(x))；若拒绝，则从归一化的正残差 max(0,p-q) 采样，补回 p 超出 q 的部分，因此合计恰好为 p。

``` math
q(x) \cdot min(1,p(x)/q(x))\  + \ rejection\_ mass \cdot p\_ residual(x)\  = \ p(x)
```

- 多个 token 逐位置应用该规则，直到首次拒绝，再由目标修正；全部接受时还可从目标模型的下一位置分布采样一个 token。

- 成立前提是使用相同的采样变换和准确概率，例如 temperature、top k、top p 的处理口径一致。近似验证或简单丢弃会破坏分布保证。

## 4 模型蒸馏和量化的区别

**答题主线** 蒸馏用教师输出、特征或轨迹训练学生模型，改变模型参数规模或能力分布；量化降低权重、激活或 KV Cache 的数值精度，通常不改变网络层数与隐藏维度。两者可以叠加。

| **维度** | **蒸馏**              | **量化**                  |
|:--------:|-----------------------|---------------------------|
| 改变对象 | 模型容量和训练目标    | 数值表示位宽              |
| 需要训练 | 通常需要              | PTQ 可不训练 QAT 需要     |
| 主要收益 | 更少参数和计算        | 更少显存 带宽 更快 kernel |
|   风险   | 能力迁移不全 教师偏差 | 舍入误差 异常值 硬件限制  |

## 5 INT4 量化后精度下降怎么办

**答题主线** 先定位退化来自哪些层、通道、激活异常值和任务，再提高敏感部分精度，而不是直接全部退回 FP16。

- 改进校准集，覆盖真实语言、长度、领域和指令；增加样本但控制分布。

- 使用 per channel 或较小 group size、非对称 scale、GPTQ/AWQ/OmniQuant 等误差或激活感知方法。

- 保留 embedding、lm head、首尾层、attention output 或异常值通道为 INT8/FP16，采用 mixed precision。

- 使用 SmoothQuant 类缩放转移激活异常值；若 PTQ 不够，做 QAT 或量化感知 LoRA 微调。

- 确认部署 kernel 真正支持所选格式，并按困惑度、下游任务、长上下文和安全能力验证，而非只测短 benchmark。

## 6 如何从系统层面优化大模型推理延迟

**答题主线** 先把延迟拆成排队、tokenization、prefill、首 token 网络发送、逐 token decode、工具和后处理。TTFT 与 TPOT 的优化方向不同，必须用 trace 和 profiler 找主导项。

- 排队与调度：容量规划、优先级、请求长度感知、chunked prefill、prefill decode 分离、控制 batch 等待时间。

- 模型与 kernel：量化、GQA/MLA、Flash Attention、fused kernel、CUDA Graph、TensorRT LLM 或优化编译。

- 缓存与解码：PagedAttention、prefix cache、prompt cache、KV 量化、投机解码和合理采样参数。

- 并行部署：选择 TP/PP，拓扑感知放置，减少跨节点；小模型避免过度 TP 导致通信占主导。

- 产品链路：流式返回、输入截断和摘要、并行独立工具调用、区域就近接入、连接复用。用 P50/P95/P99 和质量成本共同验收。

# 面经 11 字节跳动 教育 AI 2026 年 2 月

重点是架构选择、test time compute、DeepSeek R1、多模态模型和教育产品设计。

## 1 为什么现在的 LLM 多为 Decoder Only

**答题主线** Decoder Only 用统一的 next token prediction 同时覆盖预训练、指令跟随、对话、代码和上下文学习，数据格式简单、扩展规律清晰，推理可使用 KV Cache，工程生态也最成熟。

- 海量无标注文本天然适合因果语言建模，不需要为输入输出构造不同编码器目标。

- 同一模型既处理上下文又生成答案，参数共享充分；prompt 可以统一表达分类、抽取和生成任务。

- 这不表示 Decoder Only 在所有任务上最优。双向编码、严格条件生成、语音和多模态仍常使用 Encoder 或 Encoder Decoder 组件。

## 2 Encoder Decoder 架构适合什么任务

**答题主线** 适合输入和输出角色明确、需要完整理解输入再条件生成的任务，如机器翻译、摘要、语音识别、文本到文本转换。Encoder 双向建模源序列，Decoder 通过 cross attention 读取编码结果。

- 编码器输出可一次计算并被解码全过程复用，源序列和目标序列可使用不同模态、长度或词表。

- 在检索中，双编码 Encoder 适合生成向量；Cross Encoder 适合精排。VLM 也常用视觉 Encoder 加语言 Decoder。

## 3 Test time compute 是什么

**答题主线** Test time compute 指在不更新主模型参数的情况下，推理时投入更多计算来提升答案质量，包括更长思考、并行采样、搜索、验证、工具调用和迭代修正。核心是把额外计算转化为更高成功率。

- 串行扩展：延长 reasoning tokens、自我反思、分步工具执行。

- 并行扩展：best of N、self consistency、多 Agent 候选，再由 verifier 或 reward model 选择。

- 搜索：beam、树搜索、Monte Carlo Tree Search 或程序执行反馈。

- 收益依赖候选多样性和验证器质量；成本、延迟和错误相关性会使收益递减。应画出质量计算 Pareto 曲线，并按题目难度自适应分配预算。

## 4 DeepSeek R1 的训练方法

**答题主线** 公开技术报告描述了先用纯强化学习训练 R1 Zero，再为 R1 加入少量冷启动数据、面向推理的强化学习、拒绝采样 SFT，以及覆盖帮助性与安全性的第二阶段强化学习。核心算法是 GRPO，并使用规则或模型奖励。

- R1 Zero 从基座模型直接做 RL，在数学、代码等可验证任务中出现长思考、自检和反思，但可读性与语言混杂较差。

- R1 用 cold start 数据改善格式和可读性；随后推理 RL 强化能力，再筛选高质量轨迹与非推理数据做 SFT。

- 最后进行覆盖有用性和安全性的 RL。团队还把 R1 轨迹蒸馏到较小的 Qwen、Llama 系列模型。

- 面试中应注明这是基于公开报告的流程，不把未公开的具体训练规模或内部细节当作事实。

## 5 多模态大模型 VLM 的架构

**答题主线** 主流 VLM 由视觉编码器、模态连接器和语言模型组成。视觉编码器把图像切成 patch 并输出视觉 token；连接器将其投影或压缩到语言模型隐藏空间；语言 Decoder 联合处理视觉与文本 token 并生成答案。

- 视觉侧常用 ViT；连接器可以是线性层、MLP、Q Former、Perceiver resampler 或 token merger。

- 融合方式包括把视觉 token 作为前缀输入 LLM、在语言层加入 cross attention，或使用统一多模态 Transformer。

- 训练通常分视觉语言对齐、指令微调和偏好优化。文档理解还需高分辨率切块、OCR、二维位置和动态分辨率。

- 评测不仅看 VQA，还要看 OCR、图表、空间关系、视频时序、幻觉、安全和不同分辨率下的成本。

## 6 如何将 LLM 应用于教育场景以及个性化学习路径设计

**答题主线** 先把 LLM 定位为受课程标准、知识库和教师规则约束的辅学系统，而非替代教师。个性化路径应基于知识点掌握状态选择下一活动，并通过练习结果持续更新，而不是只按兴趣生成内容。

- 学习者模型：记录知识点 mastery、错误类型、先修关系、学习速度、偏好和可访问性需求；敏感未成年人数据最小化收集。

- 内容层：课程知识图谱、题库、讲义和评分 rubric 通过 RAG 提供证据，题目与解析绑定来源和难度。

- 路径策略：诊断测评 → 确定最近发展区 → 选择讲解/例题/练习 → 即时反馈 → 间隔复习；可用 Bayesian Knowledge Tracing 或 Deep Knowledge Tracing 更新掌握概率。

- 教学交互：优先提示和苏格拉底式引导，分层给线索，避免直接泄露作业答案；对开放题给 rubric 对齐反馈。

- 评估与安全：比较学习增益、迁移、留存、公平性和教师工作量，不只看参与时长；做年龄适配、内容安全、隐私、引用和教师复核。
